# midjourney-fanart

面向 Midjourney（MJ）与 Niji 的角色同人创作 Skill：从创作想法、内容系列和画风设计，到可直接复制的英文提示词，再根据返图诊断与迭代。

用户提供角色参考图，AI 统筹提示词，用户到生成界面生图。角色资料不留档。成品只包含英文画面描述，不附带参数后缀、命令、URL 或占位符；必要的附图与界面设置另用简短中文说明。

## 使用

在支持 Agent Skills 的工具中载入整个 `midjourney-fanart` 文件夹。其他环境可读取 [SKILL.md](SKILL.md)，并按任务提供链接的资料文件；分析图片时应使用具备图像理解能力的环境。

Skill 使用自然语言与相对路径，不依赖特定 AI 平台、本机脚本或日常联网。无法编辑文件时，输出更新后的模板正文供用户保存。

可直接表达需求，例如：

> 我用 Niji 7，界面设置已经选好。根据角色图设计雨夜赴约场景，给我不带参数的提示词。

> 设计一个可跨角色复用的婚誓系列；风格还没确定，先推荐方向。

> 这是返图。我喜欢配色和服装，但人物太小、表情太冷淡。保留满意部分，修改完整提示词；如果模板有问题，一起调整。

## 提示词约定

- 完整不等于冗长。单人图通常从 40–80 个英文词起步，超过约 100 词先审查冗余；这是编辑软预算，不是模型限制。
- 先选视觉重点，再从系列和风格模板取必要信息，不机械拼接全部字段。
- MJ 和 Niji 分开适配；保留用户模型选择，尤其不为压缩而误删 Niji 所需的环境和光线。
- 反馈迭代优先定位身份、构图、审美或局部缺陷，再做少量变量对照，不一律加长提示词。
- 无参数是输出工作流约束；不承诺所有功能在所有界面都有控件，特殊限制见模型用法。

## 仓库结构

```text
SKILL.md                   入口与交付规则
references/prompting.md     提示词取舍、长度软预算与成品示例
references/midjourney.md    模型、参考图与界面用法
references/feedback.md      返图诊断、对照与修改范围
references/evidence.md      官方与社区依据及适用边界
series/_template.md         新建内容系列的格式
styles/_template.md         新建风格模板的格式
```

`series/` 与 `styles/` 目前仅包含建模格式。具体系列与画风按需求新增，可使用中文文件名；不会把示例主题自动登记为用户选定模板。

## 维护

- 用户要求新增或修改可复用方案时更新对应模板；未确定的探索留在对话中。
- 资料于 2026-10-27 核查；日常不主动追逐版本，用户要求更新或遇到实际兼容问题时核实相关来源。
- 记录适用模型，区分设计推演、用户选定和实际返图验证。本次提示词规则未做 MJ / Niji 实际生图验证。
- 使用 Git 管理历史；GitHub 提交与推送按用户授权执行。
