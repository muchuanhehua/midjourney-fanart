# 返图与用户反馈

## 先明确用户的修改目标

从反馈提取：满意并需保留、不满意并需修改、希望尝试但尚未确定。用户只说“质量差”“不像”“太普通”时，结合图中表现区分身份、构图、审美与局部缺陷，不让用户自己定位专业原因。

反馈明确就直接改。用户满意的画风、姿态或服装，不因 AI 的偏好一并重做；用户改变目标时以最新明确反馈为准。

## 把观察与原因分开

结合返图、原提示词、模板与角色参考图，并在影响诊断时核对所用模型、参考图入口及界面设置。优先利用已有对话；缺少关键信息时只问能区分主要原因的问题，不要求填完整报告。

“只拍到膝盖”是观察，“鞋履描述不够导致裁切”是待验证假设。没有返图仍可检查提示词矛盾与冗余，但不声称看到了视觉缺陷，也不确定归因为某个词。

| 观察到的问题 | 优先检查与尝试 |
| --- | --- |
| 角色不像 | 辨识特征是否准确、参考入口是否正确、换装是否冲突；不靠堆叠“same character”解决 |
| 背景空、画面平淡 | 是否写出了关键情境和光色；Niji 7 尤其需要补足所需环境，不盲目继续缩短 |
| 人物小、脸不突出或裁切不合适 | 景别、主体占比、构图与比例是否相容；删掉与目标冲突的远景或特写要求 |
| 细节杂乱、主体不清 | 装饰和背景是否争夺重点；先移除不影响主题的次要细节 |
| 画风跑偏、塑料感、渲染过重 | 主导媒介是否明确，参考图、风格词、Raw、个性化是否相互干扰 |
| 多人属性串色或关系混乱 | 人数、左右、动作归属是否清楚；必要时分步制作，不靠更长的形容词清单 |
| 整体满意，仅手部或局部物件错误 | 优先局部编辑或适量变化，保留已有成果；不把负面词包当成可靠修复 |
| 与别人的同款提示词效果不同 | 核对版本、参考图、风格代码、个性化与设置；不能由正文相同就认定条件相同 |

这些是诊断方向，不是保证有效的修复公式。画面过平与画面过乱需要不同处理，不能统一回答“多写细节”或“少写细节”。

## 用小范围对照验证

默认先交付一个最有依据的修改版。原因不清或用户希望比较时，再给 A / B 两条完整提示词：

1. 明确本轮只验证一个主要因素，例如删掉冲突画风、改景别或补场景光线。
2. 固定角色、模型、比例、附图及其他设置；只比较正文时不同时改 Stylization、Raw 和风格参考。用户界面没有固定 Seed 的入口也能进行对照，不追加参数。
3. 看同批结果中的成功比例与稳定倾向，不只挑一张幸运图。若随机波动仍妨碍判断，可建议小规模复核，不无限重抽。
4. 从角色辨识、核心内容、构图、目标画风和局部完整性分别判断，用户满意度优先；保留有效改动，撤回无效假设。

固定 Seed 在支持的操作途径中可辅助比较，但不保证相同结果，也不能保存角色或风格。换模型时重新判断风格适配，不承诺旧提示词逐字复现。

## 修改范围

| 问题范围 | 应修改的位置 |
| --- | --- |
| 本张姿态、裁切、局部服装或个人偏好 | 本次完整提示词或局部编辑建议 |
| 系列共同规则持续无法表达主题，或用户明确调整系列 | 对应 `series/` 模板及本次提示词 |
| 风格定义不清、规则冲突，或用户明确改变画风 | 对应 `styles/` 模板及本次提示词 |
| 参考图入口或界面设置不符 | 代码块外的附图与设置说明，不向正文补参数 |

单张图的偶发瑕疵不足以证明通用模板有错。模型资料只在用户要求更新或实际兼容问题需要核实时调整，不因局部瑕疵重写所有版本资料。

## 交付修改

简短说明“保留什么、改变什么、下一轮看什么”，给出无参数的完整新版提示词和必要的附图说明。涉及可复用模板时说明具体改动；没有文件编辑能力则给完整替换正文。

区分设计推演、用户选定和真实返图验证；未经生成只能说“针对问题做了调整”，不能说“质量已经提升”。
